就地编辑：输入框尺寸对齐原文 + 淡化边框与外阴影

要求：点 title / 描述 / 标签进入编辑时，输入框的盒子要和被替换的文本逐像素一致，并且 尽量淡化边框和外阴影，别让卡片高度闪动。本页把跳动来源量化到像素（读数是浏览器实测的， 不是算的），并给三个「编辑感怎么画」的变体；三个变体的尺寸完全一样，只为隔离「编辑态长什么样」这一个变量。

描述框为什么必须先把 `rows` 设成 1：`scrollHeight` 不会小于元素自身的高度，默认的 `rows=2` 会让一行描述也被撑到 38px。 描述框要按内容自动长高，需要 8 行 JS（挂载与每次输入时按 `scrollHeight` 设高，夹在 19–38px 之间）； CSS 的 `field-sizing: content` 能一行搞定，但它要求 Chromium ≥ 123，不支持时会静默退回固定高度、 把跳动又带回来——所以我选 JS。

③ 长描述（5 行）在两种策略下的区别

列表里的描述固定截断在 2 行（37→38px）。编辑时要跟它对齐，就只有两条路：框内滚动，或者继续长高。

编辑时能看到全文，但点下去就长高 57px、提交后又缩回来——正好是你不想看到的两次跳动。

④ 要你定的三件事

  1. 编辑态怎么画：E2 一层淡底（推荐） / E3 淡底 + 内侧下沿（想留一点"这里能输入"的框感） / E1 无痕（只有光标）。
  2. 长描述：策略 A 封顶两行 + 框内滚动（推荐，高度零变化） / 策略 B 跟着内容长高（编辑时看全，但提交前后各跳一次）。
  3. 标签编辑框的宽度：固定 108px（推荐，宽度不参与本次"不闪动"目标） / 跟随文字宽度（更贴合，但要用 `field-sizing: content`，旧 Chromium 会静默退回固定宽度）。

另外两条我打算直接做，除非你否掉：① 编辑态的文字颜色 / 字号 / 字重与原文完全一致（含「已完成」卡的标题、空描述的斜体占位）； ② 标签编辑态沿用它自己的蓝色洗底（换成灰底会让胶囊在点击瞬间变色）。
